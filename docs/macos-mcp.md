# Database Workbench macOS package

此打包方式把 Swift 原生窗口、WKWebView、数据库 Web 后端和前端静态文件放进一个 `.app`。声明的最低系统版本是 macOS 13，本次实际验证为 macOS 27.0.1 / Apple Silicon，尚未在 macOS 13 或 Intel 真机验收；构建脚本支持在 Intel Mac 上生成本机架构产物，不生成 universal 二进制。

## 构建与启动

环境需要 Node.js 22.13+、pnpm、Rust 1.88+ 和可用的 Xcode Command Line Tools / macOS SDK。首次构建前按仓库说明安装依赖。

```sh
pnpm install
pnpm build:macos
open "target/macos-mcp/Database Workbench.app"
```

构建命令只有两个可选开关：

```sh
pnpm build:macos --force
pnpm build:macos --zip
```

`--force` 重新检查/构建各层并保留 Cargo 缓存；`--zip` 额外创建本地测试压缩包。Apple Silicon 上的主要输出是：

- `target/macos-mcp/Database Workbench.app`
- `target/macos-mcp/Database-Workbench-macos-arm64.zip`（指定 `--zip` 时）

前端、Rust 后端、Swift 启动器、应用图标和组装阶段分别缓存，源码、构建环境或输出校验变化时才重建相应层。后端使用 `CARGO_PROFILE_DEV_DEBUG=0` 的开发配置，保留增量编译能力；该命令没有 `--release` 选项，也未启用 release LTO。首次 Rust 编译仍可能较慢。

应用使用通用数据库图标，macOS 图标由 `apps/desktop/public/workbench.svg` 生成。包内保留项目 `LICENSE`，若仓库提供 `NOTICE` 也会一并保留。

应用采用 ad-hoc 签名，尚未完成 Developer ID 签名和 Apple 公证；这是可在本机验证的产物，不应当视为已完成面向外部用户的正式发行流程。

本工作区也提供 `../build-dbx-macos.command`，可双击构建，或从终端传入 `--zip`。脚本使用本工作区已安装的 Rust/Node 工具链；其他机器请使用上述通用命令。

## 运行架构

```text
Database Workbench.app
└── Contents
    ├── MacOS       Swift 原生启动器 / WKWebView
    └── Resources
        ├── dbx-web 后端可执行文件
        └── web-dist 前端静态文件

WKWebView ── HTTP /api ─┐
                       ├── 同一 dbx-web / AppState ── 数据库驱动
外部 MCP 客户端 ─ /mcp ─┘
```

启动器只监听 loopback，默认地址为 `http://127.0.0.1:4227`，可通过 `DBX_DESKTOP_PORT` 指定其他端口。原生外壳使用包内的 `dbx-web` 与 `web-dist`，不依赖另行启动的开发服务器。

GUI 继续调用现有 HTTP API；MCP 复用已有核心操作和同一进程的连接、配置与状态。本方案没有把全部 GUI 操作改成 MCP 调用。SQL 收藏的检索、读取、新建以及查询历史搜索已有明确的 MCP 入口，复用 GUI 使用的存储；文件导入导出、收藏更新/删除和完整结构编辑等操作仍未因本次扩展自动成为 MCP 工具。

启动器持有后端标准输入管道，启用 `DBX_EXIT_ON_STDIN_CLOSE=1`。关闭应用会关闭该管道并触发后端退出；启动器异常结束后，管道 EOF 也用于回收子进程。独立部署的 `dbx-web` 默认不启用这项父进程绑定。

原生退出异步等待，不阻塞窗口；先留出 15 秒完成后端正常清理，再发送 TERM，18 秒仍未退出才发送 KILL。重启会等待旧进程确实退出后再启动，避免端口和数据目录竞争。

这套窗口提供原生编辑菜单、文件选择和保存对话框。原 Tauri 的系统钥匙串桥接、文件关联/文件监控、独立分离窗口和自动更新没有在此轻量外壳中移植。

## 数据、认证与 MCP 连接

桌面应用的数据目录是：

```text
~/Library/Application Support/DBX MCP Desktop
```

其中包含 `web-password`、`mcp-token`、`mcp-client.json`、`runtime.json` 和 `backend.log`。密码与 MCP token 属于凭据，请勿把这些文件加入版本控制或随测试报告分享。客户端配置与运行信息以实际生成的文件为准。

使用原生菜单“工作台 → 显示 MCP 客户端配置”可以定位连接配置。数据目录权限为 0700，凭据和配置文件为 0600；可用 `DBX_DESKTOP_DATA_DIR` 指定绝对路径，默认目录与原先的基础开发服务器数据分开。

需要独立测试实例时，可用 `DBX_DESKTOP_DATA_DIR` 指定另一个绝对路径，并配合 `DBX_DESKTOP_PORT` 避免端口冲突。启动器会锁定数据目录，防止两个桌面实例同时使用同一份配置。

原生启动器为 Web 登录和 MCP 分别配置凭据。MCP 通过 token 文件启动，显式限定允许的 `Host` 为本地监听地址和端口；客户端连接 `/mcp` 时需要 `Authorization: Bearer <token>`。MCP 是 Streamable HTTP，不是启动另一个 stdio MCP 服务。修改桌面端口后，应使用新的本地地址更新客户端配置。

MCP 工具能力与数据库权限是两层限制。客户端能列出某个工具，并不意味着当前策略允许执行它；应在应用设置里配置允许的连接和只读策略，再连接外部客户端。

## 当前 MCP 能力范围

源码注册 32 个静态工具。Web 后端禁用两个需要 GUI 桥接的工具（`dbx_open_table`、`dbx_execute_and_show`）；基础构建未启用 MQ 管理，再排除 `dbx_peek_messages`、`dbx_send_message`。

- 默认 flat 插件模式还隐藏三个插件发现/调用元工具，因此基础 Web 构建通常列出 **25 个**静态工具。
- 此原生启动器设置 `DBX_MCP_PLUGIN_TOOLS=lazy`，保留 `dbx_plugin_list`、`dbx_plugin_tools`、`dbx_plugin_call`，因此当前基础包列出 **28 个**静态工具。
- 实际 `tools/list` 还受工具策略、插件、构建特性和版本影响。28 是本次扩展后的基础包验收值，不是所有部署的固定保证。

现有工具覆盖连接/数据库/表发现、表结构、例程信息、存储过程/函数 DDL、SQL 查询与批量执行、会话和事务操作、Redis 命令、模式上下文、连接管理及部分 Salesforce 操作。是否能使用取决于对应驱动、连接类型和策略；显式事务工具当前主要用于本地 MySQL 后端。

存储过程和函数通过已有的 `dbx_execute_query` / `dbx_execute_batch` 写入，无需新增工具或原生窗口入口。脚本按连接方言处理 MySQL `DELIMITER`、PostgreSQL dollar quote、SQL Server 单独一行的 `GO` 和 Oracle 单独一行的 `/`，具体 DDL 由目标数据库及驱动支持。目标连接/数据库在“设置 → MCP”中的有效权限需要为“完全访问”，并允许对应执行工具；连接只读、生产库保护和数据库账号的 DDL 权限仍生效。

修改前先调用 `dbx_list_routines` 和 `dbx_get_routine_source` 获取并保留原定义，提交修改后再次读取源码核验。MySQL 修改例程正文需要显式 `DROP` 后 `CREATE`；DDL 会隐式提交，重建失败不会自动恢复原例程，因此不要为该脚本启用 `use_transaction` 或使用显式事务会话。完整 MySQL JSON 示例见 [MCP 使用说明](content/docs/mcp.cn.mdx#创建和修改存储过程函数)。此处说明执行入口，不代表本地 SQLite smoke 已覆盖真实数据库的例程创建。

本次新增四个工具，将已有 SQL 工作流接入同一存储：

| 工具 | 用途 |
| --- | --- |
| `dbx_list_saved_sql` | 按连接和数据库作用域检索 SQL 收藏，默认每页 20 条，最多 100 条 |
| `dbx_get_saved_sql` | 通过收藏 ID 读取 SQL 正文 |
| `dbx_save_sql` | 在指定连接和数据库作用域内新建 SQL 收藏；不执行 SQL，也不覆盖已有收藏 |
| `dbx_search_history` | 搜索 SQL 查询历史，支持搜索词、成功状态和游标分页；仅检索 `source=sql`、`activity_kind=query` 的记录 |

新建 SQL 收藏后，GUI 的 SQL 库和 HTTP API 可读取同一条记录；GUI 经 HTTP 保存的查询历史也可通过 MCP 搜索。历史输出不包含 MCP 内部调用参数、结果或审计元数据。保存包含写入语句的 SQL 文本与执行该语句是两项独立操作；`dbx_save_sql` 只保存文本，后续执行仍受连接权限与 MCP 查询策略限制。

调用时应选择连接和数据库作用域；省略数据库时使用会话或连接默认值。收藏列表只返回摘要，读取正文使用 `dbx_get_saved_sql`；名称限制为 1–255 个字符，读取和保存的 SQL 文本最多 64 KiB。新工具目前只支持默认 catalog。历史记录没有 schema 身份，因此在限制到具体 schema 的 MCP 会话中，历史搜索会明确拒绝请求。

历史搜索每条记录的 SQL 最多返回 16 KiB，错误文本最多 2 KiB，按 UTF-8 字符边界截断。返回值包含 `sql_truncated`、原文的 `sql_bytes` 和 `error_truncated`；长 SQL 的完整正文仍可从 GUI 历史读取。此限制只影响 MCP 返回内容，不改写已存历史。

基础包未包括加密 SQLite、DuckDB sidecar、DynamoDB 或 MQ 管理能力。后续如需这些功能，应单独处理构建特性、原生依赖、打包资源和验收用例。

## 表详情跳转与定位

SQL 编辑器 Cmd/Ctrl + 左键点击物理表名，默认进入表结构详情的字段页；可按导航设置默认打开 DDL。不会在定义跳转时执行 SELECT。同一表的重复跳转复用详情标签，SQLite 冷缓存与树元数据的命名空间会统一。带引号的名称保持原样，注释与字符串不触发对象导航；文档、连接或页签改变后取消过期异步跳转。

详情页、表数据页和数据库侧栏工具栏均提供定位按钮。定位会显示侧栏、清理目标路径上影响显示的搜索条件、展开父节点并选中滚动到表。多 Catalog 严格匹配，未加载且超出首批列表的表暂需先加载对应列表，避免错误定位到其他 Catalog。

验证使用打包产物的 web-dist 与 dbx-web、临时独立数据目录及 SQLite 示例库，通过实际页面的 Cmd 点击、隐藏侧栏与搜索过滤后的定位、查看数据（4 行），以及先点击、再加载树、再 Ctrl 点击仍复用同一详情标签。类型检查及导航/侧栏/设置/工作区相关回归通过。浏览器截图：`.dbx-dev/table-definition-locate.jpg`。本轮没有在运行中的用户桌面窗口重启或变更真实连接。
